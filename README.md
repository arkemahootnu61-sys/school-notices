# 西电通知雷达

**本人手动点击一次，采集一次。没有定时任务、开机自启或自动采集。**

详细进度、数学历史专项验收、各来源实际结果与剩余限制见 [进度报告](进度报告.md)。

只关注通知、公告、公示，以及竞赛报名、选拔、培训安排、赛程等；排除新闻、校报、微博、宣传报道与获奖喜报。不自动操作成绩、个人档案、奖助申请等业务。

## 日常使用（Windows）

本机项目目录：`D:\workspace\PI\FirstProject\school-notices`。项目使用独立的 `.venv`，不修改全局 Python；浏览器功能使用电脑已有的 Chrome，不自动下载浏览器。换电脑或环境损坏时先运行 `setup.bat`，需要 Python 3.10+ 和 Chrome。

1. **连接学校允许的网络。** 校外需要学校授权的 aTrust 时由本人连接，本工具不配置 VPN、不绕过网络准入。
2. **双击 `run.bat` 打开本地控制台。** 打开页面只读取本机已保存数据，不请求学校网站。不要直接以 `file://` 打开 `index.html`。
3. 在「来源设置」中勾选来源，也可直接填写各学院的网站或通知栏目网址，然后点击「保存来源」。未保存的选择或网址会禁用采集；至少保留一个来源。保存会更新 `sources.json` 并备份旧配置，无需下载、导出或导入文件。
4. 在顶部选择模式（通常保留 **auto**）和「采集 / 浏览范围」：最近 **7天（一周）、15天（半个月）、30天、90天或不限**，再点击「开始采集」。按发布日期筛选，日期未知项单独保留；切换范围立即查询已存通知，扩大范围后需再采集尚未读过的历史。页面分别显示本轮采集范围、当前浏览范围、来源列表/详情计数和翻页进度。

### 生命周期与停止

- 控制台仅绑定 `127.0.0.1`，默认端口 8765；默认端口被其他程序占用时自动选空闲端口，不接管其他程序。
- 同一配置与输出目录再次启动会验证并复用已有控制台，不另开采集任务。不同配置或尚未就绪的服务会明确报错。
- **关闭浏览器标签不会停止控制台。** 服务只在本人主动启动期间运行；空闲时点击「关闭控制台」，或在终端按 Ctrl+C 结束。
- 「停止」请求取消当前任务，等待已有有限超时的请求结束后回滚，不强杀浏览器。Ctrl+C 同样等待任务释放资源后退出。取消不覆盖上次已提交结果。
- 一次只运行一个采集或登录任务，不排队；CLI 与控制台也通过同一私有目录的锁互斥。任务期间不能保存或添加来源。
- 控制台地址中的临时令牌用于本机访问验证，不要转发地址或私有连接文件。令牌失效时重新双击 `run.bat`；页面请求失败会保留旧数据并提示，不用空列表掩盖错误。

### 本人登录（不是自动登录）

在页面点击「学校登录」，可选择需要登录的学校来源。在弹出的**专用可见 Chrome** 中本人输入账号密码、处理验证码，并访问目标站点；统一认证完成不代表每个站点都已认证。窗口保持打开，回控制台点击「我已完成登录，保存并关闭」。只有明确点击后才保存，会提示「会话已保存」，不声称全部站点登录成功，也**不会自动开始采集**。随后本人点击「开始采集」。提前关闭窗口或取消不宣称保存成功，保留旧会话。

校园网连接与账号登录是两件事。aTrust/校园网限制需要本人连接授权网络，登录按钮不能修复网络准入。普通 Chrome 的登录状态不与本工具共享；会话可能过期，没有永久登录保证。损坏的会话文件会明确报错，请本人重新登录，不会静默清空私有数据。

## 近期通知与本轮变化

- **近期通知**（默认）：从本机 SQLite 读取成功保存的通知，默认最近 30 天，同时保留日期未知项。可以按来源、标题/摘要/来源名搜索并翻页，无需再次采集。关闭来源只影响后续采集，不删除历史通知。
- **本次发现/变化**：来自最近一次已提交报告，仅含首次收录、新发现、内容变化。第二次采集可能没有变化，但「近期通知」仍有之前保存的内容。旧版运行未记录完整结果时会明确提示未记录，不拼造旧结果。
- **首次收录**：建立基线时发现的通知，也包括其后才完成的首次积压补采，不代表刚发布。
- **新发现**：已有基线后首次发现，仍可能是旧通知，应结合发布日期判断。
- **内容变化**：同一通知的标题、日期或正文摘要来源文本发生变化；不对所有图片与附件做版本比较。
- **已收录**（内部状态 `seen`）：已保存且未发现变化，**不表示本人已经阅读**。每条显示原文链接、日期未知说明和上次成功读取时间；上次读取不是本轮一定重检过。

相同正文的转载可合并来源与备选链接：摘要长于 60 字符时按正文指纹合并，否则按通知身份区分；不会仅因标题相同就合并。不能保证识别所有改写转载。

`output/latest.html` 及带时间戳的 HTML/JSON 是**单轮增量报告**，不是近期通知库；CLI 默认省略未变化项，`--include-seen` 可展示本轮读取到的未变化项。报告文件逐个原子替换，报告写入失败时本轮数据库、候选队列、尝试顺序与来源初始化回滚；不截断上一份完整的 `latest.html`。控制台以数据库已提交结果为准。

## 覆盖结论、公平补采与上限

每来源保留读取计数、可靠列表数、详情失败数、问题代码/阶段、限额原因和待处理候选数，不按中文提示前缀猜状态：

| outcome | 页面含义 |
|---|---|
| `checked` | 已检查：有可靠检查依据，未遇到错误或限额 |
| `partial` | 部分覆盖：有可靠列表或成功详情，但有错误或限额 |
| `unrecognized` | 未识别列表：读到了页面，但无可靠列表/明确空列表，也无成功详情 |
| `failed` | 失败或受限：没有成功读取且发生访问错误 |
| `not_attempted_budget` | 本轮未尝试（预算不足）：仅因全局预算未发业务请求 |

整轮仅在所有来源均 `checked` 时为 `checked`；所有来源都无可靠列表/成功详情时为 `failed`，其余为 `partial`。顶部显示来源成功/部分/失败/未尝试数量和原因。**全源失败的空列表表示「本轮采集失败，未成功读取通知来源」，不是「没有新通知」。** 普通 HTTP 200 也不等于识别成功。

候选及尝试顺序持久化：先处理符合本轮日期/标题关键词条件的未尝试候选，之后按较早尝试顺序重检；实际详情失败也推进顺序，避免失败条目一直堵住后续通知。每次完成运行后轮换来源起点，使有限全局预算下的后续来源有机会。robots 门禁阻止或未发业务请求时不推进详情尝试。待处理数量只代表**已发现、符合本轮条件的候选**，不是全站剩余通知数。

列表分页进度也按来源入口范围持久化。每轮优先刷新栏目首页，再从上轮未读的历史页继续，不再永远重复前两页；每栏目只允许 1 页时优先推进已保存的历史页，走完后重新刷新首页。页面失败保留该页待下轮重试；取消、异常或报告写入失败不推进已提交进度。URL / 栏目入口改变后使用新范围，不沿用旧入口的分页进度。界面分别给出范围内详情数、日期过早候选数、日期未知数、已识别日期跨度和待继续翻页的栏目数；“不限日期”不取消单轮请求预算。

默认边界：

- 每入口最多 2 页；每来源最多 16 次列表页读取尝试。
- 每来源最多尝试 25 个详情；全轮最多 150 个详情。
- 全轮最多 200 个业务网页读取（不含 robots 与连接重试）。
- 每主机至少间隔 1 秒，遵守更长的 robots crawl-delay；请求超时 15 秒、有限重试。
- 单页读取上限 3 MB，不批量下载附件。

只沿允许域名的通知入口、通知子栏目与明确下一页，不遍历所有链接。限额代码为 `pages_per_seed`、`source_list_pages`、`source_details`、`global_pages`、`global_details`。日期不明会进入详情补充；通用解析仍可能需要站点适配，不能保证一次穷尽全部通知。

## 网络与 robots 门禁

默认直连；HTTP、专用登录与浏览器采集均不依赖系统代理或 `127.0.0.1:7890`，不修改 Windows 代理、VPN、校园网设置，不关闭证书验证。确需系统代理时显式使用 `--system-proxy`，`--direct` 显式选择默认直连。

- **auto（默认）**：先 HTTP，仅连接失败、超时、读取中断允许一次受限 Chrome 后备（**后台无窗口**，不弹浏览器）。业务页要求登录时，仅已有专用 profile/state 才可尝试专用会话读取，不会自动登录。
- **http**：只用 HTTP，不创建 Chrome。
- **browser**：强制专用 Chrome 只读读取（**后台无窗口**）。Chrome 缺失或不可用明确失败，不自动下载；auto 下不影响其他可正常 HTTP 读取的来源。

> 采集用 Chrome 以 headless 方式运行，不会弹出窗口；只有「学校登录」需要本人输入账号密码，才打开可见窗口。

TLS、代理错误、明确 HTTP 错误、拒绝访问、校园网限制、验证码不换通道；无列表也不猜测 JavaScript 自动启动浏览器。采集禁止自动 POST/PUT/DELETE、填写表单、自动认证跳转及非允许域名请求；必须用 POST 读列表的站点不会因此放宽规则。

**每次业务读取都先检查同 origin 的 `/robots.txt`。** auto 仅可在 HTTP 网络中断后对同一 robots 地址用 Chrome 后备，不改路径、不降级 HTTPS、不扩大域名。404/410 可视为无规则文件；401/403 或明确禁止为拒绝。登录、验证码、普通 HTML/系统错误页不当成空规则；429/5xx 不当成不存在。默认无法核实即保守跳过，报告 `robots_unavailable` / `robots_invalid` / `robots_denied`。有效规则和读取失败按 origin 在本轮缓存，HTTP/Chrome 共用节流和声明的 User-Agent。

控制台提供默认关闭的逐来源「本人许可」开关，对应配置布尔值 `allow_robots_unavailable`（缺省 `false`）。仅本人明确保存许可后，规则读取的 `connection_failed`、`timeout`、`read_interrupted`（含空响应）才允许继续读取该来源允许域名内的公开通知；同域其他来源不会继承许可。明确禁止、401/403/429/5xx、无效规则、登录/验证码、TLS、代理和不安全跳转错误仍拒绝，业务页的访问检查不变。报告保留 `robots_unverified` 警告；成功读取也只能是 `partial`，不能标为 `checked`。当前 11 个重点来源按本人本轮确认启用，新建配置及新增网站默认关闭；修改网址会清除旧许可。

robots 规则解析复用 [Scrapy](https://github.com/scrapy/scrapy) 采用的 [Protego](https://github.com/scrapy/protego)，不再自行使用标准库的简化匹配方式。支持最长路径优先、同一 User-Agent 多组规则合并、UTF-8 BOM 和小数 crawl-delay，避免把明确允许的子目录错误拦截，或漏掉另一组的禁止规则。网络读取仍复用 Requests 与 Playwright，通知历史 / 公平候选属于本项目业务逻辑。

已下载 Scrapy 源码参考，并在本机虚拟环境安装 [curl_cffi](https://github.com/lexiforest/curl_cffi) 0.14.0 做独立网络对比；该客户端对数学学院 robots 地址也没有读到有效响应，因此没有把更换库说成已经采通，也没有额外加入一条自动重试通道。生产新增依赖为 Protego，已写入 requirements.txt。

**浏览器能打开主页，不等于该浏览器或脚本能读取 `/robots.txt`。** 默认模式下 `robots_unavailable` 表示在规则下载阶段停止，尚未请求通知主页；显式许可继续后则另报 `robots_unverified`。不能据此断言网页坏了、解析失败、一定要校园网或一定遭遇反爬。auto 两通道均失败时，说明会保留 `HTTP[错误码]；Chrome[错误码]`，不再只显示最后一次错误。没有实际 403 / 429 / 验证码等证据时，不把普通连接中断标成反爬。

## 高级命令行与导入

以下命令在项目目录运行；日常仍使用控制台，不需要导出/导入。`run-all.bat` 独立执行一次 `run --all`，不会启动控制台；遍历所有当前配置候选仍受上限，可能慢且含未适配/需登录来源。

```powershell
# 本地控制台；端口 0 自动分配，不自动打开浏览器
.\.venv\Scripts\python.exe notices.py serve --port 0 --no-open --output output

# 单轮增量采集：默认 auto；只临时选这些来源，不改保存的开关
.\.venv\Scripts\python.exe notices.py run --only S03 S04
.\.venv\Scripts\python.exe notices.py run --all
.\.venv\Scripts\python.exe notices.py run --http --days 60 --include-seen
.\.venv\Scripts\python.exe notices.py run --browser --only S38

# 标题关键词初筛（任一匹配），不是控制台的本机全文搜索
.\.venv\Scripts\python.exe notices.py run --keyword 竞赛 --keyword 报名

# 扩大预算会增加访问量；仍不代表全站穷尽
.\.venv\Scripts\python.exe notices.py run --pages-per-seed 5 --max-list-pages-per-source 24 --max-pages 400 --max-details 250 --max-details-per-source 60

# 高级手动登录：本人操作后，保持窗口打开，回终端 Enter 保存
.\.venv\Scripts\python.exe notices.py login

# 来源维护，写操作与控制台/采集共用互斥锁并备份旧配置
.\.venv\Scripts\python.exe notices.py sources list
.\.venv\Scripts\python.exe notices.py sources add "某学院通知" "https://example.edu.cn/notices/"
.\.venv\Scripts\python.exe notices.py sources enable S10 S22
.\.venv\Scripts\python.exe notices.py sources disable S09
.\.venv\Scripts\python.exe notices.py sources remove M01
.\.venv\Scripts\python.exe notices.py sources import "C:\Users\feng\Downloads\sources.json"

# 全局配置/私有目录参数放子命令之前；用于独立配置与数据
.\.venv\Scripts\python.exe notices.py --config "D:\notice-config\sources.json" --data-dir "D:\notice-private" serve --system-proxy
```

`--days 0` 不限日期，不取消请求/分页上限。`serve` 支持 `--port`、`--no-open`、`--output`、`--timeout`、`--delay`、`--direct` / `--system-proxy`，没有对外绑定的 `--host` 参数；采集模式和天数在页面选择。`run` 的 `--http` 与 `--browser` 互斥，不指定就是 auto。

`run-browser.bat`、`login.bat` 仍是高级单轮采集/终端登录入口。`import-sources.bat` 可选择普通来源配置 JSON；导入后在控制台重新载入来源即可，不需要旧离线筛选页。来源可配置 `seed_urls`、明确的 `allowed_hosts`，以及 `list_selector`、`detail_link_selector`、`title_selector`、`content_selector`；不使用全域通配符，不扩展到个人业务。修改配置时先结束活动任务，保留备份并查看校验错误。

## 私有数据与无损升级

默认私有目录 `%LOCALAPPDATA%\XidianNoticeRadar`，可用全局 `--data-dir` 指定：

- `browser-profile/`：专用 Chrome 资料，是持久 Web Storage 的主体。
- `browser-state.json`：补充恢复会话 Cookie 的保存文件；**不应把仅有 Cookie 的快照当作完整 localStorage/Web Storage 恢复保证**。
- `notices.sqlite3`：成功通知、来源初始化、候选与尝试顺序、已提交运行结果。
- `console/connection.json`：本实例的私有连接元数据与临时令牌，不应共享。

profile/state 可能含有效凭据，未额外加密，依赖操作系统用户目录权限。不得上传、发送、同步或提交到 Git。控制台不会提供这些私有文件。清理会话请先退出工具，再由本人删除 profile/state；无需删除通知数据库。脚本不索取密码，不把通知发送第三方；报告可能含校内内容，不要公开发布。

旧数据库 `PRAGMA user_version=0/1` 在独立事务内升级为 **2**，保留通知、来源初始化、运行结果、候选顺序、正文指纹和首次/末次记录时间；新增 `list_checkpoints` 保存栏目历史翻页进度。重复打开不重复迁移，高于支持版本的库明确报错且不修改文件。旧通知未记录的正文解析状态、旧运行结果仍为 NULL，来源在重新发现前为未知，不按域名猜测、不重置为新发现。数据库版本和报告 `schema_version` 是独立概念，当前恰好均为 2。

## 项目文件

- `output/`：单轮报告；旧报告不重写。
